# PubMed translation checks for regional search terms

On November 15, the native grapefruit Japanese and tarragon Cyrillic expressions sent correctly encoded regional terms, but PubMed reported a translation consisting of literal OR terms. The provider returned 12,283,123 hits for each malformed query. The earlier attempts harvested 79,553 irrelevant candidates before reaching a provider partition limit. Follow-up stopped those unfinished metadata downloads. Those candidates count toward neither evidence nor coverage. [Original grapefruit receipt](grapefruit-before.tsv) · [Original tarragon receipt](tarragon-before.tsv) · [NCBI ESearch documentation](https://www.ncbi.nlm.nih.gov/books/NBK25499/#chapter4.ESearch)

The native tool now checks the returned root translation before date partitioning and ID admission. An unexpected literal Boolean term or blank field phrase fails the query, while preserving the provider count, translation and reason. Unit cases cover both failures, a mixed Latin and Japanese expression, accents, and explicitly requested operator words. Guarded live replays rejected Japanese, Cyrillic and Persian expressions in one request each with zero IDs. Four grapefruit queries still completed and harvested 13 distinct PMIDs. An all-Latin expression with incomplete translation of some phrases still retains the provider's omissions in its warnings. [Guarded grapefruit queries](../grapefruit-stride-replay/pubmed-queries.tsv) · [Guarded regional tarragon queries](../tarragon-facial-expression-replay/regional-pubmed-queries.tsv) · [Native guard](../../tools/foodexperiment.pubmedquery.pas)

Direct translation probes also found cases where quoted non-Latin terms became blanks or were omitted while valid Latin terms stayed in the translation. The guard addresses the visible invalid structures. Usable translated subsets and regional searches still need provider-specific coverage and exact-source checks.
