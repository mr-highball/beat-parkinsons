The native assessment merger takes the current assessments, a fresh output path, and one or more batch TSVs with the same header. It checks claim IDs, duplicate claim and study pairs, evidence roles and local file paths. For source annotations, use `assessmentmerge annotations BUCKET OUTPUT BATCH` with a leading `bucket` or `period` field in each batch. This checks the local note and declared text file for the selected bucket. Review each candidate TSV before copying it into the catalog or experiment ledger.

An interrupted claim search can resume into a fresh output directory by adding the previous output directory after `claims`. The program verifies counts and result ranks before it reuses completed queries. Incomplete queries are requested again and the previous files remain available. The ingredient mode uses `ingredients` before the same optional checkpoint argument. A retry can also supply an API sort expression and a page size after the checkpoint directory. The page size controls each HTTP request, and pagination continues to the end of the results.

For a query that times out with core metadata, the identifier replay saves the input and output cursors and source IDs after each page. Repeating the command against the same output directory validates the saved pages and resumes with the next cursor. The identifiers provide a retrieval audit for locating missing metadata and full text.

The date-and-pain replay resumed from page 153 after HTTP 503 and finished after 176 pages. The sorted ID file has SHA-256 `1101a8d3b9e3f6110e4ccd6d547f7d9e9e08597d0aa53eb5e183c591c2a459a7`. [Date-and-pain IDs](0502-2-source-ids.txt)
