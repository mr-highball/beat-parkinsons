## Native replay

`foodexperiment.openalex resume QUERY_TSV PRIOR_CAPTURE_DIR FRESH_OUTPUT_DIR` validates the exact ordered query plan, prior audit, reconstructed result rows, and saved JSON pages. Complete routes are reused from the prior capture. For a partial route with saved pages, the tool compares the result count and ordered work IDs on the last saved page before appending. A changed boundary or unavailable page leaves the attempt partial. The new directory can serve as the next capture. The prior directory remains available for comparison. Recovery from an inconsistent or abruptly terminated capture requires reconciling its ledgers and pages first.

The native tool was compiled with range, overflow and I/O checks. Offline fixtures exercised a repeated resume, a changed count and ranking, duplicate and short pages, true zero returns versus zero-page failures, malformed prior captures and abstract reconstruction. Live replay confirmed both successful extension and rejection of a changed boundary. Matching a single boundary does not verify the rest of a mutable provider ranking. Queries above the provider's 10,000-result offset limit require authenticated cursor retrieval.
